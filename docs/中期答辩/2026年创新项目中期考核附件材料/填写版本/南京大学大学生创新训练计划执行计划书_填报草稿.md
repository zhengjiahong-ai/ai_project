## 二、项目简介

本项目面向高校学生和科研初学者在英文论文阅读、术语理解、文献批判性分析和研究问题梳理中的实际需求，拟开发一个基于大语言模型与检索增强生成（RAG）的学术论文 AI 辅助阅读平台。平台支持用户上传 PDF 论文，自动完成论文解析、章节结构提取、摘要与关键内容概括，并围绕当前论文提供对话问答、划词术语解释、逐页翻译、批判性阅读报告、背景知识补课、苏格拉底式引导学习和深度研究任务等功能。

项目采用前后端分离架构：前端基于 React、Vite、Tailwind CSS 与 PDF 阅读组件构建交互式论文阅读界面；Java 后端基于 Spring Boot 提供统一 API 网关、会话记录与服务转发；Python AI 服务基于 FastAPI、GROBID、DashScope 大模型、向量检索与内部工具注册机制实现论文解析、RAG 检索、问答推理和结构化报告生成。系统可通过 Docker Compose 编排前端、Java 后端、Python AI 服务、GROBID 解析服务，并预留 Neo4j 知识图谱增强能力。

## 五、实施方案

### 1. 系统架构方案

项目采用“前端交互层 - Java 网关层 - Python AI 服务层”的分层架构。

前端交互层负责 PDF 阅读器、侧边功能面板、用户输入、任务状态展示和本地缓存。用户在浏览器中上传论文后，可在同一阅读界面中完成论文摘要查看、划词解释、聊天问答、逐页翻译、批判性分析、背景知识补课和深度研究任务管理。

Java 网关层负责对外提供统一 `/api` 接口，屏蔽 Python AI 服务内部接口差异，同时保存论文记录和聊天历史。该层降低前端与 AI 服务之间的耦合度，也便于后续增加鉴权、限流、日志和多用户管理。

Python AI 服务层负责主要智能能力，包括 PDF 解析、结构化摘要、RAG 检索、大模型问答、翻译、批判性分析、背景知识生成、苏格拉底式问题生成和深度研究任务调度。该层通过 GROBID 获取论文结构，通过向量库和 BM25 召回相关片段，通过 DashScope 大模型生成最终回答，并在任务链路中加入证据判断、预算控制和安全包装。

### 2. 核心功能实现方案

#### PDF 解析与论文结构化

用户上传 PDF 后，系统调用 GROBID 对论文进行结构化解析，提取标题、摘要、章节、正文片段等信息；再通过智能分块策略生成适合检索的文本块，并为后续问答、翻译和分析建立 `pdfId` 关联。

#### 对话问答与术语解释

用户围绕论文提问时，系统先根据问题和当前论文上下文生成检索查询，优先从当前论文片段中召回证据，必要时补充内部文献库检索。回答生成前进行证据质量判断，降低脱离论文内容的泛化回答风险。划词解释功能会结合选中文本、页面上下文和论文片段生成简明解释。

#### 逐页翻译

系统按当前页提取可翻译文本，结合论文骨架和页面上下文生成译文，并在前端进行页级缓存。翻页时自动更新译文，避免重复请求，同时减少用户在论文阅读和翻译之间切换的操作成本。

#### 批判性阅读

批判性阅读模块围绕论文贡献、方法设计、实验论证、局限性和过度主张风险生成结构化分析。后续重点是将每条判断与论文证据片段绑定，提升报告可信度和可追溯性。

#### 背景知识补课

背景知识模块根据论文主题和用户知识水平生成概念节点、学习路径和补课清单，帮助用户先补齐理解论文所需的前置概念。后续将继续优化概念去重、节点稳定 ID 和图谱布局。

#### 苏格拉底式学习

系统根据论文结构、阅读进度和用户回答生成一组递进问题，通过问答方式检查用户理解。每轮回答后给出掌握度评估、证据判断和回读建议，帮助用户从被动阅读转向主动理解。

#### 深度研究任务

深度研究模块将用户研究问题拆解为 3-5 个子问题，围绕当前论文和内部文献库进行检索、证据判断和报告综合。当前任务状态保存在 Python 服务内存中，后续可根据需要增加持久化、任务恢复和更细粒度的进度追踪。

### 3. 安全与可靠性方案

- 将论文正文、RAG 片段、页面上下文和用户上传内容统一视为不可信输入。
- 对“忽略之前指令”“泄露 API Key”“执行命令”“联网搜索”“调用工具”等潜在提示注入内容进行检测和包装。
- 限制 deep research 的子问题数量、自动重试次数和上下文预算，控制长任务成本。
- trace 只记录阶段状态、截断摘要和错误摘要，不记录 API Key、完整 prompt、完整论文全文或系统提示词。
- 通过前端测试、Python pytest、Java 测试和 Docker 启动检查保障主要功能稳定性。

## 八、风险分析与应对措施

| 风险 | 表现 | 应对措施 |
| --- | --- | --- |
| PDF 解析质量不稳定 | 不同论文版式导致章节、表格、公式提取不完整 | 使用 GROBID 作为基础解析工具，增加异常兜底和文本清洗策略，针对典型论文样例建立测试集 |
| 大模型回答不够可控 | 回答可能脱离论文证据或出现幻觉 | 强化 RAG 证据绑定、检索质量判断和回答前证据检查；在界面展示来源片段 |
| 长任务耗时较高 | 深度研究、批判性分析可能响应慢 | 采用异步任务、进度轮询、上下文预算限制和最多一次自动重试策略 |
| 提示注入风险 | 论文正文中可能出现诱导系统越权的文本 | 将论文内容包装为不可信输入，限制工具调用范围，过滤敏感指令模式 |
| 前后端接口不一致 | 功能扩展时字段变更导致联调成本升高 | 维护接口约定文档，新增功能优先走统一 Java 网关，并补充前端服务层测试 |
| 演示环境依赖较多 | Docker、GROBID、模型 API Key 等可能影响现场演示 | 提前准备本地演示环境、截图/录屏备份和脱网展示方案 |
