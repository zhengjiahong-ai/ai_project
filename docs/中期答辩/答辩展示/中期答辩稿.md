# Pixiu Academic Assistant 中期答辩稿
各位老师好，我们的项目是郭兰哲老师指导的基于DeepResearch的科学研究大模型聚合体，产品名字是貔貅 学术论文 AI 助手。  
这个项目面向学术论文阅读场景，目标是构建一个支持论文阅读、问答、分析和研究的 AI 学习工作台。下面我将从项目背景、系统架构、基础功能、核心创新、中期成果和后续计划六个方面进行汇报。

首先是项目背景。我们在阅读英文论文时，遇到的困难其实不只是语言问题。第一类困难是论文本身阅读阻力，术语、方法和实验细节理解成本比较高；第二类困难是学习者自身的知识缺口，不知道学哪些背景知识才能读懂文章，也难以在大模型丝滑的回答下判断自己的掌握程度；第三类问题是论文本身可能存在过度表述，也就是表面上有创新，但可能是已有方法的组合或包装；第四类问题来自普通 AI 工具本身，它们可以回答问题，但很难把论文阅读进一步推进到开放研究问题。 

因此，我们希望 Pixiu 不只是帮用户“看见论文”，而是进一步帮助用户理解论文、追问论文、评价论文，并把阅读延伸到后续研究。

## 以下快进
接下来介绍项目定位。Pixiu 的定位是一个面向论文阅读的 AI 学习工作台。围绕一篇论文，我们希望形成一个连续工作流：用户上传 PDF 后，系统进行篇章解析；在阅读中，用户可以进行对话问答、划线解释和全景翻译；遇到知识缺口时，系统提供背景补课；需要检验理解时，系统提供引导式学习；进一步地，系统还可以做批判性阅读和深度研究来分析论文并开展后续研究。  
也就是一套按“输入、理解、追问、分析、研究”组织起来的阅读流程。

从技术架构上看，系统采用 **React 前端、Spring Boot 网关、FastAPI AI 服务** 的三层架构。  
前端主要负责阅读功能面板，后端网关负责统一接口和请求转发，AI 服务负责论文解析、检索和模型分析。整体服务通过docker容器编排，便于本地联调和后续部署。  

下面介绍基础功能。基础功能解决的是“论文能进来、能读、能问、能翻译”的问题。  
第一是篇章解构。用户上传 PDF 后，系统会解析标题、摘要、章节和正文片段，并把这些内容整理为后续检索和分析可以复用的结构化数据。  
第二是 RAG 问答和划词解释。用户可以围绕当前论文直接提问，系统会优先检索当前论文片段，通过意图识别和证据判断生成。同时，阅读过程中遇到术语，也可以进行划线动态解释。  【可以指一下课件对应图片】，
第三是全景翻译。它围绕当前 PDF 版面进行翻译，图表区域留空，以保留页面排版关系，使译文和原文形成对应。  

这三类基础功能共同构成了系统的底座。
# 重点讲
在基础功能之上，我们重点建设了四个核心创新功能。

第一个是 **批判性阅读**。  
它围绕贡献、方法、实验和局限四个维度进行证据化分析。系统会输出 基于证据的真实贡献、薄弱点、可能的夸大风险 和 当前缺失的证据 四个信息【可以指一下课件右边四个区域图片】，做出明确标记。  
这部分功能主要解决的是论文中的“伪贡献”问题。我们希望用户不仅知道论文“说了什么”，还能够判断论文哪些贡献真正有证据支撑，哪些地方可能实验或论证并不十分充分。【可以指一下课件结论图片】，

第二个是 **背景补课**。  
很多时候读不懂，是因为用户缺少前置知识。背景补课功能会按照不同知识水平，生成概念图谱和学习路径，并把学习路径组织为基础概念、方法前置、实验理解和批判视角等部分。  
这样用户可以先补齐理解所需的知识，再继续阅读。

第三个是 **引导式学习**。  
这个功能旨在解决“看懂了AI的讲解，但其实没有真正掌握”的问题。系统通过五轮递进问题，引导用户围绕研究问题、方法创新、方法逻辑、实验依据和局限改进进行主动学习，再据此给出反馈和建议【反馈可以强调一下课件图片里的】。
和普通问答不同，它不是直接把答案给用户，而是通过提问、反馈和回读建议，帮助用户真正理解论文。

第四个是 **深度研究**。  
深度研究面向更开放的论文分析或选题准备场景。用户输入一个研究问题后，系统会把问题拆分成 3 到 5 个子问题【展示五个子问题图片】，再调度检索，最终形成结构化报告。  
因为论文阅读往往不会停留在“读懂这一篇”。用户还会继续追问：这个方向还有什么问题？这篇论文能不能支撑某一个选题？下一步应该怎么查、怎么比较？深度研究就是把单篇论文阅读进一步推进到开放研究问题的拆解、答疑和结构化输出，直到形成研究路径。

同时我们也关注工程可靠性。AI 论文阅读工具特殊在于会直接接触上传的论文，而论文本身可能包含干扰模型的内容。因此项目中把论文内容视为不可信输入。并对于“忽略指令”“泄露 API Key”等注入内容，系统会进行检测和包装。  
同时，Deep Research 限制为当前论文，不主动扩展外部 Web 搜索；其trace 只记录阶段状态。
这些设计是为了让系统在具备智能能力的同时，仍然保持清晰的权限边界。

目前的中期成果可以概括为两部分。第一，架构已经搭建完成，PDF阅读和对话的基础功能已经可用，安全防护也已经形成初步能力；第二，批判性阅读、背景补课和引导式学习已经有较高可用度，深度研究已经完成基本逻辑闭环；
因此，项目已经形成了一个能完整运行、能围绕论文阅读流程展开的系统。

当前仍然需要改进的地方主要有：一是 PDF 解析和翻译仍然会受到复杂版式的影响；二是 Deep Research 目前完成了基本逻辑闭环，但在任务调度和报告产出上还有升级空间。  

针对这些问题，我们后续会沿着两条主线推进。
一条是工程稳定性，重点包括优化基础效果、强化证据可追溯性、完善安全防护。
另一条是智能体化，重点是进一步完善深度研究功能，并把系统扩展为论文阅读智能体。
右侧展示的是我们设想的三阶段演进路线。第一阶段是规则驱动阅读助手，在现有功能基础上提供阅读建议，比如生成阅读路线，并根据用户问题推荐背景补课、引导式学习或批判性阅读。第二阶段是轻量 Planner，让模型参与下一步阅读规划，根据论文结构和用户知识水平，判断下一步该做什么，并自动选择合适工具。第三阶段是多步骤论文阅读智能体，支持**连续**任务执行、多轮工具调用和中间结果反馈，记录用户的阅读状态和理解进度，最终帮助用户完成一篇论文的理解、检查和批判分析。

## 可能提问与回答

### 1. 你们和普通大模型问答有什么区别？

普通大模型更像泛化问答，而我们的系统围绕当前论文组织工作流。它不仅回答问题，还会优先检索当前论文证据，并提供批判性阅读、背景补课、引导式学习和深度研究等面向论文阅读的功能。

### 2. 你们的核心创新点是什么？

核心创新点是四个：批判性阅读、背景补课、引导式学习和深度研究。它们分别对应论文评价、知识补齐、主动理解检查和开放研究推进。

### 3. 基础功能和创新功能怎么区分？

基础功能解决“论文能进来、能读、能问、能翻译”的问题，包括篇章解构、RAG 问答、划词解释和全景翻译。创新功能是在此基础上进一步提升论文理解和研究能力。

### 4. 什么是论文伪贡献问题？

论文伪贡献是指论文表面上宣称有创新，但实际创新可能很有限，可能只是已有方法的组合、包装或轻微改动。批判性阅读就是希望帮助用户识别这种贡献和证据之间不匹配的情况。

### 5. 为什么需要背景补课？

很多论文读不懂不是语言问题，而是前置知识不足。背景补课可以根据论文主题和用户水平生成概念图谱、学习路径和补课清单，帮助用户先补齐理解论文所需的知识。

### 6. 引导式学习和普通问答有什么区别？

普通问答是直接回答用户问题，引导式学习则通过递进问题检查用户是否真正理解论文，更强调主动回忆、反馈和回读建议。

### 7. 为什么需要深度研究这个功能？

因为论文阅读经常会延伸到开放研究问题，比如这个方向还能怎么做、下一步该查什么。深度研究把问题拆成子问题，再进行证据检索和报告综合，让系统从“帮助理解论文”升级为“帮助形成研究路径”。

### 8. 深度研究现在做到什么程度？

目前深度研究已经完成基本逻辑闭环，包括任务创建、子问题拆解、当前论文和文献库检索、证据判断、报告综合、轮询查看和取消等。后续还会继续优化任务调度、报告质量和工具标准化。

### 9. 你们项目和 MCP 有关系吗？

MCP 更准确地说是后续扩展方向：我们已经有内部工具注册和任务调度基础，未来可以探索把这些能力通过 MCP adapter 做标准化映射。

### 10. 安全边界怎么保证？

我们把论文正文、页面上下文和 RAG 片段都视为不可信输入，对提示注入、密钥索取、执行命令、联网搜索等内容进行检测和包装。Deep Research 也限制在当前论文和内部文献库范围内，不自动扩展外部 Web 搜索。

### 11. 当前系统能跑通吗？

可以。当前系统已经完成整体联调，基础功能可以跑通，批判性阅读、背景补课和引导式学习有较高可用度，深度研究完成基本逻辑闭环。

### 12. 下一阶段最重要的工作是什么？

下一阶段重点是稳定性和可信度：优化复杂 PDF 解析与翻译效果，强化 RAG 证据绑定和可追溯性，完善提示注入防护和 trace 脱敏，并继续打磨深度研究和跨功能工作流。
