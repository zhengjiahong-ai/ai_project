# 批判阅读实施与验收记录

对应设计：[CRITICAL_READING_DESIGN_20261011.md](CRITICAL_READING_DESIGN_20261011.md)。交互总设计见 [INTERACTION_DESIGN_20261010.md](INTERACTION_DESIGN_20261010.md)。本记录区分已实现的行为、真实案例结果和尚不能据此保证的内容质量。

## 实现结果

批判阅读从统一对话进入，以“完整观点”组织回答和成果。事实与推断继续独立校验，但不再用前三条原子事实决定用户看到多少个观点。每一观点保留结论、支持关系、稳定ID、材料身份和引用；主要结论失效则整个观点不发布。无足够依据时提供部分结果，不填充第二点。

成果复用任务内保存、搜索、编辑、历史版本和原对话定位。重新核查先准备输入草稿，由用户发送后执行；沿用原问题和目标论文，保存新版本并保留旧版本。旧对话中的观点不静默绑定新版；用户修改的正文不成为论文事实。

## 设计规则与验证边界

| 设计要求 | 当前实现与证据 |
| --- | --- |
| 允许材料与批判对象分开 | 请求保留allowedPaperIds/targetPaperIds/primaryPaperId；当前论文单篇语义不扩大为逐篇批判；多篇对象不明确时先澄清，最多四篇。专项Python、前端与Java检查覆盖。 |
| 完整观点，事实和推断独立引用 | 保留组、结论角色、支持依赖和稳定ID；关键结论被拒绝时不留下孤立事实冒充观点。两观点四claim夹具验证完整呈现。 |
| 用户点数、字数和句数 | 按观点选择，短预算不截半句、引用或必要条件；每点70字与全文70字分开解析。只有一项有效判断时明确部分结果。 |
| 直接实验证据优先 | 问题驱动取证保留结果、设置、消融、限制/反例；机制说明不被当作实测失败；未检索到不等于论文没做。离线覆盖，真实内容另人工审阅。 |
| 数值和引用身份 | 继续严格绑定表格、行列、指标、比较条件；消融编号仅在选中摘录中确有对应编号时作为身份文字使用，不绕过测量数值绑定。 |
| 观点重要性与重复合并 | 同组/同topicKey确定性合并；问题与重要性由生成和人工审阅共同验证，不声称字符串规则解决科学语义判断。 |
| 总判断不扩大结论 | 独立校验总判断，其依赖引用必须属于已发布观点；更强的孤立总结被删除。 |
| 引用支持整句 | 新增方法、指标、GS、全属性量化建议、训练视角外推和恢复措辞的保守检查。中文紧贴SSIM也能触发检查。这些规则不等于完整语义证明。 |
| 半句与跨页限定 | 完整句子可保留到600字符，仍受总摘录预算约束；长英文正文缺句尾时不支持批判结论。真实检查发现“变化可忽略”漏掉下一页“镜面反射”，因此新增此项防护。 |
| 逐观点来源 | 对话和成果默认结果优先，来源在观点后折叠；展开不调用模型。跨论文与能力组合引用重新统一编号。 |
| 原文位置 | 批判观点中的原文按钮按完整摘录扫描当前任务的本地PDF，唯一匹配才跳转；不再直接相信索引页码。重复、短摘录或无法匹配时保留当前成果并提示无法唯一定位。 |
| 历史、编辑与重新核查 | 服务端维护生成版本和引用身份；浏览器不能伪造结构化批判事实。恢复版本保留当前内容；过期版本请求拒绝；重新核查不制造同ID重复成果。 |
| 历史观点追问 | 当前观点绑定保存版本；旧对话对应生成请求与现成果不一致时提示打开当前成果或历史版本，禁止静默替换。 |
| 部分、生成和保存状态 | 覆盖缺口与执行成功分开；不重要候选被拒不自动变部分结果，明确要求两点而只有一点则部分结果。 |
| 新手支持 | 提示词允许必要术语短括注，最多一项具体后续建议；不自动启动学习。尚未新增参与者实验，不能把提示词要求宣称为已验证的理解提升。 |
| 调用开销 | 不新增默认规划或重写模型调用，无自动模型补跑；固定真实案例保存原始结果，不无限重试。 |
| 旧成果 | 保留旧文本和历史，不迁移、不自动生成观点关系，也没有增加旧项目导入。 |

## 真实案例记录

材料是用户统一授权的公开LightGaussian与原始3DGS。单篇案例只取LightGaussian正文，另一篇仍属于任务允许材料但不成为本轮批判对象。任务ID为`critique-final-20261011`，界面标题“新版批判阅读验收”。

本轮保留了6次原生PDF合成诊断、2次Java/RAG真实操作、2次最终修复后的固定真实操作。每次固定输入只提交一次，全部原始结果见`critique-evidence-20261011`。前期诊断包含错误绑定、引用不完整和语义过强的结果，不列为内容通过。原生PDF诊断不是索引/API验收。

另有精确缓存离线重放及2次真实缓存恢复：`runtime-regenerated.json`和`runtime-retried.json`。其追踪在`runtime-final-traces.json`：每例llmCalls=0、llmCacheHits=1、retryCount=0，外部搜索=0。显式恢复请求不等于内部自动重试。

这些缓存重放发生在最终跨页完整句尾修复之前，证明的是原答案复用和版本链路；它们不是最终内容质量结果。最终内容以`runtime-complete-focused.json`和`runtime-complete-review.json`及对应追踪为准。

修复前的主要问题是：恢复与改善混淆、同一段落的指标被嫁接到不包含指标的引用、建议中的对照/GS依据不在该推断自己的引用内、长句被截掉范围限定。已保留原始输出，修复后不靠改写旧答案伪造通过。

最终聚焦案例`runtime-complete-focused.json`：执行成功，**部分结果，一项判断**。判断限定于作者报告的剪枝恢复消融，不宣称所有场景无损；短回答保留完整结论及引用，并说明其余待核查。未保留依据不完整的另一项。

最终全面案例`runtime-complete-review.json`：执行成功，**两项完整判断**及独立总判断。第一项是质量、存储与速度取舍，第二项是跨高斯表示的适用边界；事实标为作者报告，推断采用“可能/目标格式验证”，没有宣称已独立核验泛化。每个结论句不超过70字。引用主要来自论文摘要/引言里的作者总结，因此通过的是本轮回答的组织、身份和措辞检查，不是对整套实验的独立复核。

| 人工内容审阅项 | 聚焦案例结论 | 全面案例结论 |
| --- | --- | --- |
| 是否直接回答问题 | 回答画质保持所依赖的一个实验流程条件；不能声称已覆盖请求的两项条件，partial明确。 | 回答体积/帧率取舍和目标表示验证两个使用决策。 |
| 观点是否独立且重要 | 保留剪枝后恢复这个与质量直接相关的判断；未将不同模块无依据凑成两项。 | 一个涉及资源与质量，一个涉及换表示是否可直接套用，关注点独立。 |
| 引用是否支持整句 | 独立引用作者Pruning & Recovery消融完整句；不再使用缺“镜面反射”限定的半句。 | 每个事实和推断分别选择完整作者陈述；总判断引用均属于已发布观点。作者总结不能替代完整实验证明。 |
| 推断强度是否适当 | 限于作者报告的该消融，不提升为普遍必要条件，也不证明目标域失败。 | 以作者报告和“可能”区分事实/推断，目标格式须验证，不扩大成所有高斯表示通用。 |
| 新手是否能说清理由 | 文本包含“去冗余后执行恢复”的理由；这是人工可读性审阅，未进行新的真人理解测试。 | 资源收益对应轻微质量代价，迁移对应目标格式验证，理由可读；真人理解提升未新增验证。 |

## 交付边界

当前已实现完整的分组、证据、版本和交互契约。自动检查仍只是保守规则，不能保证每篇论文都能稳定选出最重要的两三项判断，也不能独立证明引用的语义蕴含。真实聚焦案例仍只有一项有效判断；其余内容需要新的完整证据和用户显式继续，不默认增加模型调用。

索引的全局页码元数据没有在本次重建。逐观点引用通过原PDF定位修复可用性；导航列表和全局来源中的旧索引页码仍只能作为索引提示。跨页完整引用、多重匹配和图表区域定位尚有更进一步的精细定位空间。
