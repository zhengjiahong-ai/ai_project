## 最终产品边界

1. 任务就是工作区，组织论文、对话、学习活动、笔记和成果。任务材料默认可用；显式约束优先，继续活动保持原对象，“这篇论文”以当前阅读焦点为主。
2. 统一左导航、中栏论文/成果、右对话；三栏可收起、调宽和恢复。取消单篇/多篇及独立 Agent 的主界面分裂。
3. 自然语言与六个命令 `/精读 /补课 /自测 /批判 /比较 /研究` 共用能力路径；综合 Agent 在内部按需组合能力。普通问答保持轻量。
4. 引导新手理解论文、补足前置知识、练习和验证理解，支持岔开提问后继续。掌握判断依据回答证据，不依赖固定题数。
5. 输出以结果为主，来源和执行细节收束；长成果在中栏编辑。目录、划词解释、全景翻译、标注和引用定位保留。
6. 数据可保存、恢复、迁移；长任务可停止、重试和恢复；失败或切换任务不丢内容、不串材料、不重复扣费式调用。

## 阶段 0：建立真实运行基线

**目标：先知道现有链路实际能走到哪里。**

- 核对现有实现、接口、启动方式与旧入口，建立当前缺口表，避免重做已经完成的模块。
- 启动前后端与必要服务，用真实论文走上传、解析、阅读、问答、保存、刷新流程。
- 核验真实 Provider 配置、数据库持久化与服务重启。测试环境的模型调用次数设上限。
- 若浏览器安全策略阻止本地访问，记录限制并通过允许的方式解决；不得用另一自动化入口绕过。

**交付：** 可复现启动说明、真实运行证据、阻塞与缺陷清单。

**完成门槛：** 至少一条真实论文基本链路通过；无法执行的环节明确标记未验证，不能用模拟测试替代。对应 A02、A14、A18 的基础部分。

## 阶段 1：任务数据与执行可靠性

**目标：让任务能够安全地保存和继续。**

- 固化任务、材料范围、活动、成果、来源的共享接口契约；服务端校验材料归属和严格约束。
- 统一请求身份、状态与冲突处理。学习和研究创建超时后能查询是否已执行，重试不会重复创建或重复调用。
- 补齐学习取消、活动历史和恢复；确认研究取消实际停止后台工作，区分取消请求与取消完成。
- 处理刷新、服务重启、断网、迟到响应和双客户端更新；失败草稿可找回，冲突不静默覆盖。

**交付：** 一致的任务执行状态及恢复机制、可靠的数据契约。

**完成门槛：** 异常用例通过，取消/恢复实测，任务切换不串写；服务重启后保留任务与可恢复活动。对应 A05–A07、A12、A18、A19。

## 阶段 2：统一对话与能力编排

**目标：让所有功能真正从同一个对话入口使用。**

- 完善材料选择与 `@材料` 交互、显式单篇限制、多篇比较及歧义澄清。
- 六个命令与自然语言使用同一套参数、执行和结果协议；统一错误、重试与成果保存入口。
- 实现内部综合 Agent 的受控编排：按问题组合检索、解释、比较、批判和研究，不把简单问题自动升级成长任务。
- 对话先给结论或可用结果；来源默认收束，执行中仅提供必要状态和停止入口。长报告在中栏打开。
- 上传后先提供可阅读的论文文件，解析和索引状态持久化；全文 AI 分析按需执行，解析失败可查询和重试。文件可读与能够基于全文问答分别显示。

**交付：** 完整统一对话入口、六种能力协议和内部编排。

**完成门槛：** 全任务、当前“这篇”、显式材料、持续活动四种范围真实验证；六个入口可用且输出一致。对应 A03–A08、A13、A19。

## 阶段 3：新手引导学习闭环

**目标：把“能问答”提升为“能帮助新手理解”。**

- 从用户目标和已有理解选择阅读起点，连接论文结构、前置概念、论证和方法；避免首次使用先填繁重档案。
- 完善精读、补课、自测之间的连续体验；根据作答提供针对性提示、纠错、补课和再次验证。
- 支持跳过、暂停、继续、结束；术语问答后回到原学习位置，切换中栏论文不改变活动对象。
- 检验模型反馈的准确性、证据支持与教学措辞；无法评估时明确说明，不伪造掌握进度。

**交付：** 从读不懂到能够解释关键概念的一条连续学习流程。

**完成门槛：** 用真实论文验证正确、部分正确、错误、缺证据和岔开提问案例；学习界面能够继续且明确提示下一步。对应 A09、A10；不强制追加A20参与者观察。

## 阶段 4：批判、比较与深度研究闭环

**目标：形成有依据、可继续使用的分析成果。**

- 完善批判中的主张、证据、局限与可验证问题；比较输出明确论文之间的共同点、差异和适用条件。
- 研究支持简洁计划调整、确认、执行、取消、失败恢复与最终报告；保留已完成部分。
- 关键事实引用能够对应原文证据；区分材料级来源与具体论断证据，不把来源清单当作句级证明。
- 验证内部 Agent 在复杂问题下组合这些能力。外部检索依用户明确启用，默认不扩大到任务外材料。

**交付：** 三条分析链路及统一可编辑成果。

**完成门槛：** 真实多论文问题能产出有证据的结果；抽查关键论断、取消与恢复；摘要简洁、完整报告可打开。对应 A11–A13。

## 阶段 5：笔记成果整理与恢复

**目标：让研究积累能够长期保存和整理。**

- 笔记和成果按任务组织，保留多论文关联、来源与学习/研究关联。
- 补齐跨任务移动的原子性与失败恢复；旧任务来源在目标任务中仍可解释和访问，不静默丢失论文关联。
- 验收现有编辑、草稿、历史版本和恢复功能；预览、导出与最新编辑正文一致，覆盖空正文和保存失败。
- 验证已有笔记与论文缓存兼容、缺文档ID补全和原始备份；不提供旧研究项目导入功能，不进行全量历史搬运。

**交付：** 可整理、可恢复、可导出的任务成果库。

**完成门槛：** 保存失败及冲突不丢草稿，移动失败无丢失，重复请求无重复；实际版本恢复与导出内容正确，已有缓存及无ID文档兼容无损。旧研究项目导入不属于验收项。对应 A15–A18。

## 阶段 6：前端设计与完整使用体验

**目标：把各条已完成链路收束成一个成熟产品。**

- 统一排版、信息层级、组件和交互状态；完善三栏折叠恢复、调宽、任务切换与中栏论文/成果切换。
- 完善首次上传、空任务、解析中、无材料、错误与继续学习提示；让新手知道现在能做什么。
- 打磨 PDF 目录、选区解释、标注、翻译、引用坐标和返回阅读位置；处理扫描或解析不完整论文的可用提示。
- 验证宽屏、窄屏和移动端的主要流程、键盘操作及可访问性。结果、来源和进度遵循简洁呈现原则。

**交付：** 一致的界面和经过实际操作检查的主要用户流程。

**完成门槛：** 实际浏览器截图与操作记录；核心流程无需了解内部模型、执行器或接口术语。对应 A01、A13、A14；A20参与者完整观察为可选项。

## 阶段 7：完整验收与正式入口切换

**目标：完成当前设计边界，而非只宣布代码完成。**

- 对照原计划 A01–A20，记录通过、失败和未验证，保留可复现证据。
- 汇总真实 Provider、数据库重启、服务端读回、已有缓存兼容和端到端使用检查；完成相关自动测试与构建检查。独立浏览器恢复子项已由用户免验，不再追加执行。
- 保留已有新手反馈；A20完整参与者流程已由用户取消强制验收，不再安排补做，也不将未观察步骤记为通过。
- 修复阻断主流程和数据可靠性的缺陷，核验回退方案后将统一界面设为默认入口；保留迁移所需兼容入口。

**交付：** 正式统一入口、验收报告、启动和使用说明、已知限制。

**完成门槛：** 当前适用的强制项A01–A19全部满足，其中A18独立浏览器恢复子项免验；A20不阻断完成。不得把免验或未验证项目算作通过，不得以离线测试替代要求的真实功能及交互验收。

## 顺序、批次与额度控制

- 主顺序为 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7。来源数据结构、迁移兼容和界面规范在前期确定，阶段 5、6 完成全量打磨，避免后期推倒重来。
- 已实现的三栏、学习、研究、版本恢复和来源保留属于阶段基础，优先补缺与验证，不重复开发。
- 一个阶段可以分若干有完整交付的批次。每批明确范围、实施并验证；用户已授权持续完成后续全部阶段，阶段验收通过后单独汇报，再继续下一阶段。
- 默认单代理 6.1 Sol，普通批次不新开 Astra。只有确有独立边界的大任务才考虑低成本代理，不让多个模型重复读取整仓库或重复审查同一修改。
- 每批运行相关验证；阶段末做一次整体验收。真实模型案例复用，限制调用次数，不通过反复生成替代排查。
- 每批汇报只列：完成结果、验证证据、剩余问题、下一批范围。阶段通过必须注明离线还是实际运行证据。

## 用户可见的阶段里程碑

| 阶段 | 可见交付 | 验收重点 |
| --- | --- | --- |
| 0 | 项目稳定启动，真实论文基本链路可复现 | 上传、阅读、问答、保存、重启 |
| 1 | 任务可保存、恢复和继续 | 不丢数据、不串任务、不重复执行 |
| 2 | 统一对话和六种能力入口 | 材料范围正确，结果简洁，停止/重试/成果一致 |
| 3 | 新手能完成精读、补课和自测 | 能岔开提问再继续，反馈依据回答证据 |
| 4 | 批判、比较和研究形成可用报告 | 原文支持关键判断，复杂任务可调整和恢复 |
| 5 | 按任务整理、恢复与导出笔记成果 | 编辑、版本、移动、缓存兼容、导出不丢内容 |

阶段 2 的完成是统一入口可用；最终完成必须达到阶段 7。阶段 3、4 改善能力质量，阶段 5、6 完成数据和体验闭环，不能用阶段 2 的接口接通替代后续交付。
