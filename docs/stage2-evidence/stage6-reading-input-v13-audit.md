## 实际发现与修复

截取代理记录到已取消旧研究被反复GET。独立只读查询确认 `stage1-file-1791210362` / `d4979e85-585c-54b4-b666-3a710e4ece39` 的权威状态为cancelled。原Hook虽然声明了三个终态，只对succeeded停止查询，且新增研究时会重置局部终态集合。

修复后，发布状态及工作区确认完成才记住succeeded/failed/cancelled；增加其他研究不会重新轮询已结束的旧研究。显式操作会恢复GET核对，操作响应未确认时继续查询原身份，不自动重发操作；未确认成果保存仍保留查询。

26项相关前端回归通过，含三种终态、增加研究、未确认操作后的GET恢复及既有成果发布/错误隔离，类型检查与生产构建通过。实际修复后的页面使用同一只读代理观察：旧截取期间该cancelled身份查询71次；新页面约55.66秒的观测窗口前后均为1次，总数未增加。两段观察时长不同，不把71与1解释成精确性能比例。该实测只覆盖真实cancelled分支，另两终态由回归覆盖。见`stage6-research-poll-v13-runtime.json`及tests/typecheck/build日志。
