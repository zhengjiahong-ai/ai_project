# 批判阅读完整设计

本设计承接 `INTERACTION_DESIGN_20261010.md`：任务组织材料、对话启动能力、结果优先、来源折叠、成果在中栏打开。本文是待实施的专项设计，不表示下列改动已经实现。本次只编写设计，不运行新增模型案例。

## 1. 目标与当前问题

批判阅读帮助用户判断：论文的哪项主张得到什么支持、成立到什么程度、会影响怎样的理解或使用。新手读完应能说清一个具体判断及其理由，而不是记住一串“优点/缺点”。

当前演示请求要求检查“压缩后画质几乎不变”的适用边界、只给两点。实际回答先介绍SH蒸馏，再讨论训练视角，随后介绍剪枝机制；第二项推断藏在“补充结论”。两组讨论又集中于同一个视角覆盖问题。

代码原因：`grounded_critique._atomic_findings`把每组observation/inference展平；生成展示时取`findings[:3]`。通用对话适配器随后再按文字预算截取。内部事实拆分正确，但展示丢失了观点分组和用户要求的点数。

本次需要同时解决：问题选择、证据覆盖、观点组织、整体摘要、来源追溯和验收。只换Markdown标题不能解决这些问题。

## 2. 功能入口与材料

- 自然语言或`/批判`进入，既有精读、自测、比较、研究仍复用统一对话入口。
- 任务论文默认是允许使用的材料，不等于每轮必须逐篇批判。内部区分“允许材料”和“批判对象”。
- 明确指定论文时以指定对象为准；“这篇/当前论文”以当前打开论文为批判对象，其余任务材料只在确有必要且允许时作为比较背景。允许使用不等于必须加入回答，不能把另一篇的结果或限制嫁接到当前论文。
- 单论文取证与合成继续只接收该论文的证据。确需跨论文判断时，由上层按论文身份组合独立结果或采用比较组织；不能直接混入多篇摘录，破坏现有单论文校验边界。
- 明确“分别批判这两篇”才建立两个论文对象；“比较两篇的证据是否公平”采用比较组织，避免并列生成两份无关联报告。
- 没有明确对象、当前也没打开论文时：仅一篇可直接使用；多篇则只问一次“要看哪篇，还是分别看全部”，保留原草稿。不能随机选一篇。
- 仍遵守现有最多四篇的单次边界，不自行引入外部搜索。只有用户明确要求查外部资料才交给对应研究能力，并标明新的材料范围。
- 输入区沿用“主要参考××”等短提示；不增加批判专用设置面板。

## 3. 根据问题决定回答形态

| 用户问题 | 回答目标 | 默认呈现 |
| --- | --- | --- |
| “帮我批判阅读这篇” | 选最影响结论可信度或使用决策的问题，也可以确认有价值的证据 | 一句总判断，通常2—3个不同观点 |
| “画质几乎不变可信吗” | 围绕这项主张核对证据和适用条件 | 1—2个直接相关观点 |
| “只给两点/一句话/150字” | 优先遵守点数、长度与内容要求 | 按完整观点压缩，不填充无依据结论 |
| “实验是否公平/公式有没有问题” | 聚焦实验口径或论证链，不顺带写全面综述 | 最相关判断＋必要核对信息 |
| “从审稿角度详细评价” | 按用户要求覆盖创新性、论证、实验或可复现性 | 对话概括；详细观点及对照表进入同一份成果 |
| “这会影响我复现/选题吗” | 说明当前判断对使用决策的具体影响 | 结论＋影响；有必要时给一项可执行核查建议 |
| “解释一下第二点” | 承接对应观点和材料，不重新做全篇分析 | 对该观点的短解释或展开 |

默认简短回答目标约250—400字，属于软目标；内容简单可以更短。用户显式长度优先，长分析在成果保留。不能为了满足默认字数省略决定性的条件。

明确要求N点时，N指观点数，不是事实句子数、来源数或子调用数。若只有1项有依据的判断，就呈现1项，另用一句话说明剩余内容只能待核查。字数和覆盖范围明显冲突时给能完整表达的简答并提供成果入口；极短预算下不得额外附上超出预算的长限制说明。

## 4. 以完整观点为组织单位

每个观点围绕一个可回答的问题，通常包含：

1. **判断**：先告诉用户这一点说明了什么。
2. **必要理由**：原文报告的事实、实验或定义，保留必要条件。
3. **意义**：对主张可信度、适用范围或复现决策的具体影响；已有判断表达完整时不再复述。

外观为一个短标题和一小段正文，不强制逐项打印“判断/事实/推断/影响”四个标签。内部仍将事实和推断分别保存、引用和校验，展示按逻辑连接。

观点分为三种语义，不使用无根据的百分制评分或“高可信”等自动评级：

| 语义 | 可以怎样说 | 不可以怎样说 |
| --- | --- | --- |
| 论文报告的结果 | “在该数据集和设置下，作者报告……” | 从局部结果推成普遍结论 |
| 有依据的推断 | “这一设计可能影响……，需要区分……” | 把机制风险写成已经观测到的失败 |
| 待核查问题 | “当前材料尚不能判断……，应核对……” | 将检索未命中写成论文没有实验 |

不是每个事实都必须配一个缺点。贡献、恰当实验或合理限定也可以成为判断；批判阅读不等于强行否定论文。

### 4.1 选择和排序

- 先回应用户指定主张及其子问题，再考虑一般性问题。
- 优先影响主结论或用户决策的内容；证据强、影响小的旁枝参数不能挤掉关键条件。
- 实验性主张优先找直接结果及比较条件，机制解释只能辅助，不能替代性能证据。
- 同一“问题—影响—核对方法”视为同一关注点。不同机制指向同一风险时合并其依据；只有需要不同实验或不同决策时才分别成点。
- 按现有有效证据决定输出数量，不保证每篇必有三点、不保证正反各半。
- 若没有成立的批判结论，允许明确回答“当前证据不足以作出这项判断”，给具体待核查内容；不输出一份貌似完整的批判报告。

### 4.2 摘要

- 总判断从已通过校验的观点导出，不新增更强主张、数字或因果关系。
- 对话摘要选择完整观点；先删次要例子、重复术语和过程叙述，再压缩理由。不能按前三条原子claim或固定字符位置截断。
- 为满足很短预算，可以只保留完整结论句，但必要条件和不确定性必须一起保留。
- 详细成果保留全部有效观点及支持材料；聊天未展示的次要观点可在成果查看，不能把某一主观点的后半段藏成“补充结论”。

### 4.3 全面阅读时检查什么

这些是分析时的候选维度，不是每次必须填满的报告模板。用户聚焦某项主张时，只选择相关维度。

| 维度 | 具体核对 | 必须守住的边界 |
| --- | --- | --- |
| 主张与贡献 | 解决什么问题，论文的核心贡献与现有材料中的对照是否一致 | 仅凭本篇不能断言整个领域的首创或过时；原文的创新主张与独立确认分开 |
| 方法与论证 | 假设、定义、推导或机制是否足以支撑结论 | 不能把直觉上的担忧写成公式错误或实际失败 |
| 实验与比较 | 数据划分、基线、预算、指标和比较条件是否对应主张 | 比较对象和条件不匹配时说明影响，不能直接拼接数字排名 |
| 因果与消融 | 性能变化是否能归因到指定模块，是否存在混杂因素 | 多个模块同时变化不能直接确定单模块贡献；提出怎样隔离变量 |
| 适用范围与代价 | 哪些场景已有证据，质量、速度、资源之间如何取舍 | 区分已测试范围、作者明确限制与尚未覆盖的推断边界 |
| 可复现性 | 关键设置、资源和执行步骤能否支持用户的复现目标 | 本次摘录未找到不等于全文没提供；核查代码时须实际取得相关材料 |

最终选点按用户问题和证据决定。可执行建议要对应一个明确疑点，例如固定数据和训练预算、只替换一个模块、观察指定指标；不统一附加“增加实验、扩大数据集、提高鲁棒性”等套话。

## 5. 证据组织与质量约束

证据检索由关注的问题驱动。讨论实验结果时同时找结果、设置/基线、消融或限制说明；讨论机制时同时找定义、目标及对应代价。原文已有反例、失败场景或限定必须纳入判断。

- 数字绑定对应论文、表格行列、指标、数据集、基线及实验条件；跨阶段消融和不同硬件结果不能拼成同一比较。
- 公式、归一化和训练分布沿用已有严格核验，不用不完整摘录补造机制。
- 来源具有论文、页码、摘录身份；同一来源可支持多项观点，一项观点也可有多处来源。
- 事实和推断各自引用支持它的依据，不能通过共用一份引用让推断看似得到直接实验证明。
- 反证或相反结果不能因为降低结论完整度而被过滤。
- 当前材料不完整时只描述本次判断范围。禁止“全文已验证”“论文缺少××”等超出覆盖范围的提示。
- 若作者明确承认某限制，可写“作者指出……”，引用原文；不把所有负面措辞一律删除。若讨论“未做某项实验”，必须有明确作者说明或足以界定的检查范围，并限定陈述范围。

自动检查能证明的是结构正确、摘录身份匹配、数值关系及材料范围符合规则；引用存在本身不证明语义蕴含、因果推断或观点重要性。语义质量须通过固定案例和人工抽查验收，不用“核验通过”徽章代替。

## 6. 对话、成果和证据交互

**对话默认内容：** 总判断、选出的完整观点、必要的一句限制、一个“打开批判成果”入口。普通批判通常不画表格，不显示执行流水、轴评分、检索命中数或模型内部字段。

**成果默认内容：** 与对话一致的总判断和观点顺序，允许展开更完整的理由。每个观点保留稳定ID，用于继续追问和证据关联。

**证据入口：** 观点末尾用小型引用标记；点击展开该观点的必要摘录和页码，可跳回原文。全局证据列表仍可折叠检索，但不在顶部先铺长来源列表。不重复同时放三份相同摘录。

**待核查：** 与用户当前问题直接相关的未决条件，用一句话紧邻对应判断；其余收进“待核查”折叠区。某个关键子问题未完成时不能全部隐藏在折叠区。

**状态：** “已生成/已保存”描述执行和保存；“部分结果”描述本次覆盖缺口；“待核查”描述学术判断。三者不互相替代。一个不重要的候选观点被拒绝，不应自动把已经完整回答的问题标成部分失败。

**追问：** “第二点为什么”“展开实验条件”“把这个转成实验方案”可承接稳定观点ID及成果版本。用户修改成果后，后续分析说明使用的版本；不把用户编辑自动当作论文事实。

**新手支持：** 第一次出现且影响理解的术语可用一个短括注说明；按需展开或继续追问，不自动切进精读或自测。确有帮助时只给一个下一步建议，例如核对某表的一组条件，不默认每次安排学习任务。

成果沿用任务内保存、搜索、改名、编辑、版本和原对话定位。重新生成建立版本；点击打开或来源展开不触发模型。无需增加独立批判页面或旧项目导入。

## 7. 输出结构与生成流程

### 7.1 内部结构

采用可选的版本化结构扩展现有响应，保留`message`、`summary`、`groundedClaims`、`artifact`、来源和请求身份等外层契约：

```text
critique.schemaVersion: 2
scope: allowedPaperIds / targetPaperIds / primaryPaperId
question: 原问题及用户要求的子问题、点数、长度
claims[]:
  id / paperIds[] / kind(reported|inference)
  text / references[] / numericBindings
issues[]:
  id / topicKey / questionPartIds[] / paperIds[]
  title / conclusionClaimId / supportClaimIds[] / implicationClaimId?
  relatedPendingIds[] / priority
pending[]:
  id / questionPartIds[] / topic / whatToCheck
coverage:
  answeredQuestionPartIds[] / unresolvedQuestionPartIds[]
presentation:
  leadClaimIds[] / chatIssueIds[] / artifactIssueIds[]
```

ID均由服务端稳定生成或校验。单论文合成的claim只有一个paperId；跨论文组织若产生关系判断，须显式列出paperIds并分别引用每篇依据。标题是非断言性主题短语；包含新的事实性判断时也必须纳入claim校验。优先级只用于排序，不作为用户可见评分。

保留当前assessment分组，在组内将事实和推断展开校验，再带着组ID还原。`groundedClaims`仍可展平给既有引用组件使用，展平结果不再决定观点数和摘要边界。

### 7.2 生成与校验

1. 从既有意图解析得到批判对象、问题范围和输出要求，不新增默认规划模型调用。
2. 定向选取证据，绑定来源身份，覆盖直接支持、限制和可获得的反证。
3. 在现有合成调用中输出分组观点及独立原子claim，不增加默认“再请模型组织一次”的调用。
4. 校验材料、摘录、数字、事实/推断关系及格式。失败claim从组中移除，不能自动改标签让它通过。
5. 检查组依赖：关键结论失效则不发表该观点；支持理由失效而结论有独立有效引用时可保留较短版本。剩下孤立事实不能冒充批判结论。
6. 合并重复关注点并排序。默认只做可确定的同组/同主题合并，不用字符串相近就断定两个科学问题相同；提示词负责语义合并，固定案例核对结果。
7. 按用户子问题检查覆盖，选择完整观点形成摘要和成果。对极短预算使用已校验结论句，不生成未经核验的自由改写。
8. 统一分配显示引用编号，再生成对话和成果的引用映射。多论文与能力组合不得把不同论文的局部`[1]`错误当成同一证据。

原请求失败、停止、结果恢复沿用现有请求生命周期。默认不自动补跑、重写或重试模型；需要补充取证时，给用户可选择的下一步，沿用统一授权和执行记录。

### 7.3 部分结果

| 情况 | 返回方式 |
| --- | --- |
| 某个次要候选未通过，但用户问题已完整回答 | 输出已有完整答案，不展示内部拒绝计数 |
| 用户要求两点，只找到一个有效判断 | 呈现一个判断，说明另一项仍待核查；不补造第二点 |
| 关键主张缺少直接结果证据 | 明确本次无法确认该主张；已有机制解释不能顶替实测结论 |
| 所有结论不可用，但有具体核查目标 | 返回“暂不能判断”及少量核查目标，不显示成功的批判结论 |
| 某观点结论依赖的证据失效 | 整个观点不发布，保留其他独立观点和原问题 |
| 服务/解析失败 | 在原请求显示具体失败与恢复入口，保留已有成果，不伪装成学术上的证据不足 |

## 8. 示例：重新组织当前演示

以下是组织示意，依据当前演示已保留的机制说明，不是新增模型结果，也没有声称核对了全部实验。

> 仅凭剪枝和蒸馏机制，还不能确认“画质几乎不变”的适用范围，关键要看实际评估条件。
>
> **训练设计不能代替目标视角的质量评估。** 作者用训练视图贡献指导剪枝，并用教师与学生模型的像素差监督SH蒸馏。这些说明了压缩与补偿如何进行，但不足以单独判断目标视角下会损失多少质量。
>
> **待核查：质量代价有多大。** 进一步核对同条件下压缩前后的质量指标和细节图，判断“几乎不变”对应多大变化；当前这份回答没有给出这些直接实验依据。
>
> `查看依据`　`打开批判成果`

若取证后已有充分实验依据，应替换成具体有条件的判断；不能永久复用“需要更多实验”式空泛结论。若用户要求两点但只有一个判断，第二段仍明确叫待核查，不将其凑成第二个成立的批判点。

| 2. 范围、取证和质量选择 | `conversation_capability_service.py`区分允许材料/批判对象；`analysis_service.py`按问题选择直接证据；调整合成契约 | 单篇焦点不扩大为逐篇批判；重复关注点合并；实测与机制、反证及取证缺口区分 |
| 3. 摘要与界面 | 通用适配器增加分组摘要支持；`ChatPanel`、成果内容和引用入口复用统一布局 | 字数/点数约束、同一成果、逐观点来源、追问ID、原文往返和状态就地呈现 |
| 4. 验收与提交 | 保存离线夹具、浏览器证据及必要的固定真实案例；分阶段commit | 全部专项规则通过，内容质量人工审阅；只复测改变的能力，不重跑全部演示 |

旧成果继续按原文本读取，不迁移、不自动重生成。只有新的响应使用分组结构；旧记录缺少结构时不推测观点关系或引用身份。

## 10. 验收标准

先用离线夹具和组件测试证明契约，再在必要时执行固定真实案例；每例保存原始结果和审核结论，不以无限重跑直到满意代替验收。

| 固定场景 | 必须满足 |
| --- | --- |
| 两个观点，各有事实和推断 | 对话显示两项完整判断，不能只保留第二项事实；成果与对话顺序一致 |
| 两种机制指向同一边界 | 合并关注点、保留双方依据，不制造两个重复缺点 |
| 实验性主张，有直接实测依据 | 先回答主张和条件，机制介绍不能挤掉关键结果 |
| 只有机制依据、没有目标域结果 | 不声称目标域失败，不断言论文缺少验证；明确本次不能确认 |
| 原文有明确限制或反例 | 保留并准确表述，不被缺失措辞规则误删或被正面摘要掩盖 |
| 数字来自不同表格行/消融阶段 | 拒绝错误绑定，不发布混算结论，其他独立观点仍可用 |
| 一个关键结论未通过 | 观点连同依赖关系正确降级，孤立事实不算完成一个批判点 |
| 用户要求两点、150字或一句话 | 遵守完整观点边界、长度与必要限定；不凑数、无半句或悬空引用 |
| 默认任务两篇，提问“这篇” | 只批判当前对象；辅助材料身份明确，不把另一篇限制嫁接过来 |
| 明确多论文或解释+批判组合 | 一份统一成果；论文和引用编号不混淆；批判结论不被前置解释挤掉 |
| 展开来源、跳原文、返回、刷新 | 不触发模型；恢复阅读位置；能定位同一观点和成果 |
| “解释第二点”及用户编辑后追问 | 绑定正确观点/版本，保留任务范围；用户修改不变成论文事实 |

内容审阅另核对五项：是否直接回答问题、观点是否独立且重要、引用是否支持整句、推断强度是否适当、新手能否用自己的话说清判断理由。前四项任一严重错误即不通过；不能用测试数量抵消内容问题。

完成本设计的标准是上述行为和内容验收同时成立，不是JSON有效、引用存在或界面能显示即算完成。
