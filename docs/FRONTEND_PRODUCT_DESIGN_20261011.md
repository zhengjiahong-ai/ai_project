# 学术论文助手前端产品化设计

日期：2026-10-11。状态：设计已实施；实际验证范围见 `FRONTEND_PRODUCT_IMPLEMENTATION_20261011.md`。本文件承接 `INTERACTION_DESIGN_20261010.md` 与 `CRITICAL_READING_DESIGN_20261011.md`，规定前端整理的最终行为、视觉规范、开发顺序和验收边界。设计参数本身不是测试结果，实现及验收以对应 IMPLEMENTATION 文件为准。

## 1. 目标与保留边界

目标是让用户进入任务后，能清楚地读论文、问问题、阅读结果、保存整理、再次找回；界面的注意力集中在论文与答案。成熟度来自信息层级、统一控件、可靠反馈和连续阅读，不通过新增模块或装饰性卡片实现。

- 任务就是工作区，界面统一称“任务”，不另设研究项目或工作区层级。
- 任务材料默认允许 AI 使用；“这篇”等明确单篇语义以当前论文为主，显式指定材料优先。打开成果不应把成果关联的论文悄悄变成新的阅读焦点。
- 保留从左到右的导航、阅读、对话三栏，以及各栏收起、拖动调宽、专注阅读和专注对话。
- 精读、补课、自测、批判、比较、研究、能力组合通过自然语言或斜杠启动，产出沿用统一成果关系。翻译、划词解释、标注留在阅读区域。
- 结果优先；引用可见但摘录折叠；过程按需查看。必要的不确定性贴近对应结论，不能因追求简洁被隐藏。
- 不增加旧项目导入，不迁移旧文档、不批量重写旧记录、不默认增加模型调用。
- 本轮主要是展示和操作整理；不借此替换 PDF 引擎、编辑器或整个前端框架。

## 2. 页面结构与区域职责

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 貔貅  [当前任务 ▾]                                      [布局] [设置]       │
├────────────────┬────────────────────────────────┬───────────────────────────┤
│ 搜索本任务      │ LightGaussian              ··· │ 对话                  ⌕  │
│                │ 原文 / 译文 / 对照             │                           │
│ 论文与材料   ＋ │                                │ 用户问题                  │
│  LightGaussian │       论文 / 成果正文          │                           │
│  原始 3DGS     │                                │ 直接回答                  │
│  当前论文目录 ▸ │                                │ [引用] [打开成果]         │
│                │                                │                           │
│ 笔记与成果   ＋ │                                │                           │
│  质量保持条件  │                                │                           │
│  消融实验方案  │                                │                           │
│  学习记录      │                                │ [有新结果]                │
│                │                                │ 当前活动：仅运行时出现    │
│                │                                │ ┌───────────────────────┐ │
│                │                                │ │ 输入问题……            │ │
│                │                                │ │ 材料范围  /功能  发送 │ │
│                │ 页码 / 缩放（仅论文）          │ └───────────────────────┘ │
└────────────────┴────────────────────────────────┴───────────────────────────┘
```

中栏打开成果时，论文视图选择器和页码工具换成成果标题与编辑操作，不保留无关阅读控件。左栏负责寻找对象，中栏负责阅读和整理，右栏负责提问与承接结果；后台任务完成不会自动替换中栏正在看的内容。

### 2.1 顶栏

- 高度约 52px；品牌标识 24—28px，任务名 14px。任务标题可点击打开切换器，避免顶栏和导航重复显示两套任务选择控件。
- 任务切换器有搜索、最近任务、全部任务入口；新建任务、重命名、归档在此按上下文提供。归档与删除不混同。仅实现并验证过的动作才能进入菜单。
- 布局使用一个图标按钮打开菜单：并排、专注阅读、专注对话。当前选择有标记，悬停提供名称；不常驻三个文字按钮。
- 设置收纳外观和现有全局配置；不把功能参数、研究过程放进全局设置。
- 全局错误只用于确实影响整个应用的情况。某页翻译、某次生成或某份成果保存失败在各自位置提示。

### 2.2 三栏与自适应

尺寸是首轮调试基准，应根据真实论文、长回答和系统缩放验证，不是所有屏幕强制固定值。

| 可用宽度 | 默认布局 | 规则 |
| --- | --- | --- |
| ≥1360px | 三栏 | 导航 232px；对话约 400px；阅读区分配余量，正文优先 |
| 1100—1359px | 阅读＋对话，导航收起 | 导航按需以抽屉打开；可在宽度许可时手动恢复三栏 |
| 768—1099px | 阅读或对话主视图 | 通过清楚的切换入口往返；两栏仅在各自最低宽度满足时允许 |
| <768px | 单栏 | 阅读/对话切换，导航抽屉；输入框不被虚拟键盘或底部区域遮挡 |

- 三栏基准最低宽度：导航 200px、普通阅读区 480px、对话 340px；PDF 对照需要更大空间。宽度不足时收栏，不继续挤压三个区域。
- 用户明确选择的布局和栏宽优先保存；窗口变窄临时收栏，重新变宽恢复原偏好，不覆盖持久化偏好。
- 中栏对照翻译空间不足时建议专注阅读；若仍不足，使用同页原文/译文切换，并明确当前模式，不强行左右挤压。
- 至少保持阅读或对话可见；收起入口有名称，分隔线支持键盘调宽与复位。触屏用明确切换按钮，不能依赖拖拽。
- 论文、成果、对话独立滚动。布局变化保留页码、缩放、正文位置、选中记录和草稿。

## 3. 任务导航与记录命名

左栏顶部是“搜索本任务”，下面保留“论文与材料”“笔记与成果”两组；当前论文目录放在论文组内，可展开和收起。已有内容时不再用一块大紫色上传按钮占据空间。

### 3.1 论文与目录

- 论文行：小图标、短标题、必要的处理状态。当前正在阅读的论文有清楚的选中背景。
- 点击论文行只打开阅读，不改变显式指定的对话材料范围。作为引用跳转的论文与用户主动选择的当前论文需要在状态层正确区分。
- 加号提供上传 PDF 和已有材料选择。无论文时以“添加论文，开始阅读”为主操作；上传中允许取消，解析中可先看原文。
- 目录默认收起；展开显示当前论文目录，不为每篇同时铺一棵树。切换论文后目录内容同步，保存各论文目录展开和阅读位置。
- 标题可两行显示；完整题名通过悬停/详情查看，不能因为英文长题名撑宽导航。
- 移除操作进入行菜单，在键盘聚焦行时也能访问。符合真实可恢复能力时提供撤销；永久删除必须独立说明影响，不承诺不存在的恢复能力。
- 搜索固定在导航顶部；论文组与成果组使用两个相邻的滚动区域，导航外层不再滚动。论文组默认最多占可用列表高度的 40%，成果组占余量；展开目录使用论文组自身滚动，不新增目录内部滚动。论文组收起后成果组取得余量。低高度窗口（列表可用高度小于 320px）改为两组共用一个列表滚动区域，避免两个过短列表。

### 3.2 笔记与成果

- 全部成果按最近更新排序；筛选按钮按需选择笔记、学习、批判、比较、研究、译文。类型是筛选元数据，不是新的模块页面。
- 加号直接新建空白笔记。自动生成报告、学习记录仍沿用现有保存规则；普通回答由用户主动保存。
- 行主信息为内容标题；次要信息最多展示类型和日期。不要同时堆记录序号、页码、长论文名、完整时间。
- 学习记录可折叠分组，已结束项不出现在对话顶部；暂停、跳过、结束和已掌握状态分别表达。
- 选中成果不取消论文的阅读焦点，但左栏明确显示当前打开的是哪份成果。关联论文可作为次级提示，不伪装成当前论文选中态。

### 3.3 命名规则

| 对象 | 推荐标题 | 避免 |
| --- | --- | --- |
| 批判 | LightGaussian：质量保持的条件 | 对话成果、批判报告4 |
| 比较 | LightGaussian 与 3DGS 的压缩取舍 | 比较结果、两篇论文对比 |
| 研究 | 剪枝与 SH 降阶的消融实验方案 | 完整用户指令作为标题 |
| 学习 | LightGaussian：剪枝与压缩机制 | 超长完整论文题名＋已结束 |
| 译文 | LightGaussian · 第4页译文 | 翻译成果 |
| 用户笔记 | 用户命名，默认“未命名笔记” | 用 AI 输出替换用户名称 |

- 先使用已有结构化题目，其次从用户问题提取短主题，再使用论文短名＋功能名；不为命名新增一次模型请求。
- 视觉目标约 12—24 个中文字符，不硬切英文术语或数学符号。省略只影响列表显示，完整标题仍保存。
- 用户改名后绝不自动覆盖。同名记录保留身份，列表用日期或简短副标题区分，不用大量自动序号作主标题。
- 旧通用名称可在展示层提供安全的内容摘要兜底；不批量修改服务端旧文档，也不宣称已经建立旧数据的新结构关系。
- 自动标题提取先去除斜杠、材料标记及“帮我/请”等请求套话，再优先选择问题中的主张或输出对象，例如“剪枝与 SH 降阶的消融实验方案”。不从结果中截取半句作为确定结论。无法可靠提取主题时用“LightGaussian · 批判阅读”等诚实兜底；同题记录再以日期或版本区分。自动标题不能比正文判断更强。

## 4. 查找与恢复

“能找回”针对真实保留的数据，不包含从未保存、已永久删除或没有任何备份的不可读取数据。

| 要找什么 | 入口 | 点击后 |
| --- | --- | --- |
| 论文、笔记、报告、学习记录 | 左栏搜索本任务 | 打开对应中栏对象，并定位已支持的命中位置 |
| 某次问题或回答 | 对话搜索 | 对话定位原消息，高亮命中，显示前后文 |
| 失败、停止、等待处理的请求 | 任务切换器内的处理记录入口 | 查状态、定位原对话；明确操作后才重试 |
| 另一任务的记录 | 先搜索并切换任务 | 在该任务查找，范围始终清楚 |
| 当前成果的旧版本 | 成果更多菜单的版本历史 | 打开历史内容，明确为历史版本 |

- 搜索结果按材料、成果/学习、对话等真实对象类型分组，显示短标题与一段命中摘要；不把同一个成果与关联消息当成两份成果。
- 空查询展示最近访问；输入后筛选。搜索无结果时给具体范围提示，不默认触发网络或模型。
- 左栏搜索不随意改动用户当前阅读对象；选中结果才切换。关闭搜索恢复原列表位置。
- 搜索范围不可读或不完整时说明“当前仅搜索已加载内容”等真实限制，不声称全库搜索成功。
- 当前版本与历史版本的追问分别绑定，不能把旧消息的“第二点”静默关联到新版本。

## 5. 成果阅读与编辑

### 5.1 阅读态

```text
[返回论文]  LightGaussian：质量保持的条件         [编辑] [···]

压缩收益成立，但质量保持依赖论文采用的设置与恢复流程。

1. 剪枝后的恢复是理解质量结果的关键
   完整判断与必要理由…… [1]
   查看依据 · 追问这一点

2. 换到其他高斯表示仍需核对适用条件
   完整判断与必要理由…… [2]
   查看依据 · 追问这一点
```

- 内容前只保留一层工具栏。标题在正文前可换行；栏头可使用短标题，但不能连续显示两遍完整标题。
- 正文以一句总判断开头，然后按内容呈现。不是每个回答都强制套用报告模板。
- 更多菜单收纳重命名、定位原对话、版本历史、整理/移动、导出，以及内容适用的重新核查。没有原消息或历史版本时不显示空入口。
- 原图和图文下载放在对应来源/页内容附近。跨页成果不能在全局头部误标为“第1页”。
- 保存状态安静显示在编辑相关位置；阅读态已保存无需常驻一大块状态。部分结果、真实冲突、未保存修改需要可见。
- 正文后不强制附“总结/建议/下一步”重复段落；下一步最多一项且确实有用。

### 5.2 编辑态

- 点击编辑切换同一份成果，不新建副本；显示保存/完成编辑入口和对应保存状态。
- 保留当前可靠的保存机制，不为了视觉修改擅自改成自动保存。若未来改自动保存，需要单独定义服务端冲突、网络失败与版本行为。
- 切换对象保留草稿；回到该对象可继续。未同步修改的提示只归属对应文档。
- 保存失败保留本地内容并就地重试；冲突展示双方版本并让用户选择，不静默覆盖。
- 恢复旧版本创建可追溯的恢复状态，保留原当前内容；查看历史不等于恢复。
- 用户编辑的内容不能被标为经过 AI 核验的论文事实；引用与结构化批判关系仍按已有完整性规则维护。

### 5.3 成果与对话的关系

- 一份生成成果关联原问题、生成版本和稳定成果身份。反复打开、保存或定位不会再生成一份。
- 打开成果可短暂突出原消息，并提供“定位原对话”。不强制每次把用户正在浏览的对话滚走。
- 对话展示当前回答摘要与成果入口；中栏显示完整内容，避免默认同时重复两份长报告。
- 旧对话结果保留。其关联成果已更新时，明确“此回答对应旧版本”，提供原版本与当前成果入口；不能改写历史消息使其看似新答案。
- 从证据回到成果，恢复对应观点、展开状态与滚动位置。

## 6. 对话与输入

### 6.1 时间线

- 用户消息轻背景、靠右；助手回答靠左，正文为主，减少多层边框和每条消息重复的品牌大图标。
- 时间、复制、保存/打开、更多等操作次级展示。鼠标悬停与键盘聚焦都可访问；触屏不能依赖悬停。
- 不默认铺满搜索输入框，栏头搜索按钮展开后才占空间；搜索期间不丢当前阅读位置。
- 长报告先给直接结论和成果入口；简短问答完整留在对话。用户明确要求详细回答时可以在对话完整显示，不能机械裁剪。
- 流式内容不强制改变用户正在看的位置。接近底部时跟随新内容，向上阅读时显示“有新结果”。
- 重试结果仍关联原问题，显示必要的重试/版本关系；异步完成不插到无关的新问题下面。

### 6.2 输入框

- 一个输入容器：文本区、材料标签、功能入口和发送/停止；减少材料栏、操作栏、文本框分别形成多层区域。
- 文本区默认约 3 行，输入增长到约 8 行后内部滚动，不把整个对话推到屏幕外。
- 材料默认标签“任务材料 2 篇”；当前论文可简写为次级标签。材料弹层解释默认规则、展示候选材料和排除/指定状态。
- 明确单篇语义时提示“主要参考 LightGaussian”，不能写成“仅用 LightGaussian”而实际仍允许背景材料。
- 显式 @ 选择显示可移除标签；未读到的材料或解析未完成应及时提示。提问本身无需每轮人工确认范围。
- 输入 `/` 或点功能图标，出现有简短说明的功能选择。选择后在输入内放可取消的小标签，斜杠命令仍可直接编辑。
- 自动识别无需多一张确认卡；确有歧义或研究计划需要处理时在原消息下提供一次明确选择。
- 生成中仍可编辑下一条草稿；显示停止当前生成和发送下一条的明确入口，不能覆盖用户输入。未支持排队时不伪装成已排队。
- 中文输入法确认不发送；默认 Enter 发送、Shift+Enter 换行，可与现有偏好一致。禁止把对话快捷键用于关闭浏览器或覆盖系统操作。
- 精读作答时显示“回答当前学习问题”；切换临时追问明确可见。暂停/结束能直接找到，提示/补课/跳过按需展开。

### 6.3 当前活动

- 输入框上方仅在需要时出现一行：“研究中 · 停止”“待回答 · 回到问题”等。
- 多项活动显示数量并按需展开，不堆多张活动卡。
- 完成后退出当前活动条，结果回到原问题，记录进入导航。完成标识不等于内容已全面核实。
- 用户转做其他事情不自动中止学习，也不把普通问题自动当作作答；已有进度可继续。

## 7. 各功能的统一结果规范

共同外观：内容标题、直接结果、局部引用、适用的保存/打开入口；只有特定任务需要的交互才额外出现。结构统一不意味着所有功能都输出同样的段落。

| 功能 | 对话默认呈现 | 中栏/记录 | 关键边界 |
| --- | --- | --- | --- |
| 普通问答、补课 | 直接解释；必要术语首次简注 | 用户保存后成为同一份笔记/成果 | 不为普通短问答自动建报告 |
| 精读、自测 | 当前问题、用户作答、针对性反馈 | 历史学习记录，按题组织 | 已结束不等于已掌握；只读历史不启动模型 |
| 批判 | 一句总判断＋2—3个完整观点，显式要求优先 | 完整观点、证据、版本 | 事实/推断内部区分；不凑点数；部分结果明确 |
| 比较 | 直接回答主要区别；必要时小表格 | 统一比较成果 | 表格标明论文身份和比较条件，不混不同实验口径 |
| 研究 | 简短计划或待处理问题；完成后摘要＋报告入口 | 可编辑方案或报告 | 全文指令不重复变成卡片标题；过程默认收起 |
| 能力组合 | 一份统一结论 | 一份关联成果 | 不连续输出多个重复摘要和成果入口 |
| 翻译 | 不新增全局完成消息 | 论文原文/译文/对照；可保存页译文 | 失败归属该页；页数与版本清楚 |
| 划词解释 | 用户继续追问时进入对话 | 原位置小浮层，短解释＋展开 | 翻页或切换内容收起，不遮挡无关论文 |
| 上传、解析、概览 | 不刷聊天日志 | 论文行小状态，概览主动打开 | 完成不自动替换正在读的内容 |

批判的内容组织和校验沿用专项设计。视觉整理不能通过删除限定、将待核查改成肯定或抹去部分状态来获得“干净”的外观。

## 8. 来源、错误与状态

### 8.1 来源

- 引用编号紧贴对应事实或判断，点击展开局部依据。来源阅读不调用模型。
- 依据面板默认只显示论文短名、章节/页位置（确知时）、支持该观点的摘录和原文入口；大段检索信息进入更深层详情。
- 同一观点只有一个“查看依据”入口；全篇来源列表放末尾或更多菜单，避免与逐观点依据重复抢占正文。
- 计数分别表达论文数和证据片段数；不能把“来源2”同时用于两篇论文、两段摘录或两个引用。
- 引用定位无法唯一匹配时保留阅读位置，说明未能定位；不跳到看似合理的页。已验证的严格定位与返回行为不得回退。
- 用户自己的改写与模型推断在需要区分的地方短标注，避免每段都堆“原文/事实/推断/用户判断”四个标签。

### 8.2 状态

| 状态 | 用户看到 | 可操作行为 |
| --- | --- | --- |
| 首次加载 | 与最终内容结构接近的轻量占位 | 已缓存内容保留；避免整屏闪白 |
| 上传/解析 | 对应论文行的阶段提示 | 取消上传；解析中先读原文 |
| 正在生成 | 原问题下短状态＋当前活动一行 | 停止、编辑下一条草稿 |
| 等待操作 | 原位置显示实际问题/计划 | 选择/作答/修改；可离开再回来 |
| 已完成 | 结果本身 | 保存或打开，不显示永久成功大横幅 |
| 部分结果 | 可用内容＋具体缺口 | 阅读、保存；明确选择后核查或重试 |
| 单次失败 | 原位置简短原因，保留已有内容 | 查询状态或手动重试，取决于真实请求状态 |
| 保存失败/冲突 | 对应成果附近的明确状态 | 保留草稿、重试/对比，不静默覆盖 |
| 服务离线 | 一次全局连接提示；局部数据说明 | 继续读缓存；恢复连接不自动重发模型请求 |
| 无数据/无命中 | 一句范围明确的说明 | 添加材料、清除筛选等相关操作 |

- 不在用户普通流程中显示 requestId、JSON、重试堆栈。诊断详情在次级入口按需查看。
- 不用绿色“完成”掩盖内容不足，也不让保存成功弹窗重复打断阅读。
- 操作成功一般用轻反馈；失败和需要行动的状态可持续显示到处理完毕或用户收起。

## 9. 视觉与组件规范

风格：安静、清晰、偏学术工具。保留貔貅品牌和紫色强调，缩小装饰比重，减少大面积强调色和无意义边框。

### 9.1 首轮视觉基准

| 项 | 规范 |
| --- | --- |
| 颜色 | 应用浅灰、导航略深灰、正文白；一组紫色强调；成功/警告/错误有语义色且辅以文字/图标 |
| 字体 | 保留现有可靠的中文系统字体回退；正文 15—16px，界面 13—14px，次要信息 12px |
| 内容标题 | 20—22px；段标题 16—18px；避免每条消息都用大标题 |
| 行距 | 中文正文约 1.65—1.75，按实际字密度微调；段间 10—12px |
| 阅读宽度 | 长文约 680—800px上限，窄栏流式；正文容器 20—24px 内边距，窄屏 12—16px |
| 间距 | 使用 4/8/12/16/24/32px 级别，消除相似区域随意不同的空白 |
| 控件 | 桌面常规高度 32—36px；触屏交互范围至少 44px；小图标不等于小点击范围 |
| 圆角 | 常规 6—8px，输入容器 10—12px；减少多种圆角混用 |
| 边框/阴影 | 分栏用细边界；浮层用轻阴影；不把每个段落包成卡片 |
| 动效 | 约 120—180ms，用于菜单与状态过渡；尊重减少动画偏好 |

以上是设计参数，不是已经通过测试的结果。常规文字对比度目标不低于 4.5:1，图标、边界与焦点的关键视觉对比不低于 3:1；实际颜色需在浅色与深色主题中测量。

### 9.2 共用组件

建立并复用：按钮（主/普通/文本/危险）、图标按钮、菜单、搜索输入、材料标签、状态提示、浮层/抽屉、分栏标题、记录行、成果工具栏、引用依据、空状态。

- 同样的保存/更多/搜索/返回图标全站一致，不同页面不另造一套。
- 主按钮用于当前关键动作；一组操作通常只有一个主按钮。紫色不用同时强调上传、导出、版本历史和发送。
- disabled、loading、hover、pressed、focus、error 六种状态要完整定义。
- tooltip 补充说明但不能作为唯一名称；图标有可访问名称，键盘焦点始终可见。
- 大表格横向滚动只发生在表格区域；公式、代码和 PDF 不通过全页横向溢出解决。
- 深色模式复用同一语义变量，不逐组件写临时背景色。

## 10. 新手支持与交互安全

- 空任务提供“添加论文”与一句用途说明。上传后提供最多三个起步提问：“帮我读懂这篇”“核对一个主张”“比较这些论文”。用户用过后不常驻教程大卡。
- 功能菜单每项一句用途描述，不暴露 agent、skill、RAG 等内部概念；斜杠仍保留高效操作。
- 含术语的结果在首次出现时给必要的短括注，允许继续解释；不每次输出完整课程。
- 所有菜单支持 Escape 关闭、焦点回到触发处；抽屉/对话框焦点不会跑到遮罩后的页面。
- 用户改名、写笔记、选材料时不让自动生成结果覆盖当前操作；异步返回按原请求归位。
- 任何“重新核查/重新生成”明确会生成新结果，普通打开、查找、历史查看不能触发模型。
- 多处触发同一动作使用同一状态；双击保存不产生重复副本，连续点击重试不产生并行重复请求。
- 产品内不为每一步弹确认框；需要确认的范围由真实破坏性操作或任务计划要求决定。

## 11. 技术实施范围

当前相关入口包括 `frontend/src/UnifiedTaskApp.jsx`、`UnifiedTaskApp.css`、`components/TaskNavigation.jsx`、`TaskNavigationDetails.css`、`index.css` 和成果/对话相关组件。实施前按具体子任务再定位引用与测试，不一次重写全部文件。

- 先梳理现有样式变量，增加统一语义 token，后逐区替换；删除确认不再使用的样式须检查引用。
- 将顶栏、导航、阅读工具栏、输入容器和局部状态拆为职责清楚的组件；状态身份继续复用现有 request/artifact/activity/version 关系。
- 新命名规则是无模型的纯展示/持久化规则；用户名称与生成名称分开识别，避免更新时覆盖。
- 布局持久化区分用户偏好与当前宽度下的临时适配；不要将隐藏阅读面板等同于销毁 PDF 实例。
- 引用面板按需渲染；大列表只有测量确认存在性能问题时才引入虚拟化，不能破坏搜索、滚动和键盘操作。
- 新能力菜单只接已有真实能力；后端没有支持的筛选或搜索能力不伪装成完整实现。
- 本轮默认使用已保留的真实结果和本地测试数据验证展示，不新增模型案例、不向外部发送论文。
- 开发从已保留的空任务、双论文、批判、研究和学习数据建立展示夹具；加载/失败/冲突用受控状态模拟。文案与布局检查使用同一组夹具，避免每个区域只在理想数据下成立。模型输出质量变化若未来确有必要，另作内容改动与验证，不混入本轮视觉完成声明。

## 12. 分阶段开发、提交与验收

| 阶段 | 交付 | 依赖/建议提交边界 | 通过条件 |
| --- | --- | --- | --- |
| A 信息与操作收束 | 语义标题、成果单层工具栏、无空历史、局部依据入口、原消息关系 | 标题规则与导航一组；成果工具栏一组；消息关联提示一组 | 首屏可读核心结论；不同成果凭标题可辨；旧版本不误绑定 |
| B 视觉统一 | token、共用控件、导航/阅读/对话排版、浅深主题 | 共用样式先提交；各区域逐步替换，避免巨大混合提交 | 同类控件外观/状态一致；长标题、表格、公式不撑破布局 |
| C 布局与操作连续性 | 按宽度适配、输入容器、任务切换器、搜索入口、键盘操作 | 布局偏好独立提交；输入与搜索各自提交 | 调宽/收栏/切任务/刷新保留对象、草稿与位置 |
| D 状态与最终体验验收 | 空态、生成/失败/部分、保存冲突、撤销边界、完整截图记录 | 状态整理与验收记录分别提交 | 明确归属，无重复提交，无完成卡累积，真实结果可读 |

分阶段指可独立评审的开发顺序，不降低最终边界。每阶段提交只包含对应改动；保留仓库已有未提交日志、演示数据和用户文件。

### 12.1 自动验证

- 对新增语义行为写必要测试：标题不覆盖用户名称、旧版本关系、临时收栏不覆盖偏好、搜索定位、输入法不误发送、保存去重与错误归属。
- 保留现有功能回归；针对改动运行对应测试、类型检查、构建和修改文件检查。纯间距/颜色不写镜像样式实现的测试。
- 不用测试数量代替视觉质量；既有 lint/build 警告分别记录，不把局部通过写成全量无问题。

### 12.2 实际浏览器验收矩阵

| 场景 | 验收重点 |
| --- | --- |
| 空任务、单篇、两篇 | 起步入口明确，材料规则无歧义；不要求完成参与者新手全流程 |
| 已有批判、比较、研究、学习记录 | 默认结果简洁，来源可展开，记录标题可辨，历史可访问 |
| 长论文名、长公式、宽表格、很多成果 | 不撑宽，局部滚动合理，搜索结果能区分对象 |
| 1440/1280/1100/900/390px宽度；常见系统缩放 | 正文可读、输入框可见；三栏/双栏/单栏切换一致 |
| 鼠标、键盘、触屏 | 不依赖悬停；菜单/抽屉焦点可达，Escape与焦点恢复正确 |
| 生成中、暂停、部分、失败、离线、冲突 | 状态归属准确，内容保留，不暗中重发 |
| 原文→依据→成果→原对话→刷新 | 身份和阅读位置连续；无额外模型调用 |
| 保存/打开/查看版本/重试快速重复点击 | 不重复建档，不把查询当重试，不并行重复执行 |

最终验收须包含真实 PDF、保留的真实回答、浏览器截图和交互记录；不额外执行用户已省略的独立 Edge 恢复或参与者完整新手流程。

### 12.3 产品完成标准

1. 打开已有成果后，正文前只有一层工具栏；正常桌面首屏看得到直接结论和第一项核心内容。
2. 成果能凭内容标题辨认，搜索与原对话定位可用；不存在四份不同内容全部只能靠“对话成果＋序号”区分的默认状态。
3. 输入区可理解本轮材料与作答方式，生成/完成记录不长期占顶部；用户不需要理解内部执行字段。
4. 来源在局部可展开，重要限定与部分状态仍贴近判断；打开来源与历史不调用模型。
5. 阅读、任务切换、成果编辑和返回路径不会丢内容、位置或身份；保留现有严格引用和版本边界。
6. 常见屏幕宽度及浅深主题均无明显视觉断层；控件、焦点、错误和保存状态一致。

完成后交付分阶段 commit 清单、验证结果、已知限制与关键截图；用“设计已实施且经过这些检查”描述实际证据，不将界面整理等同于所有研究回答质量或新手理解效果均已验证。
